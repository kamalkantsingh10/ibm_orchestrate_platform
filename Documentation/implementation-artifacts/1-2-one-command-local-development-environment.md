# Story 1.2: One-command local development environment

Status: review

## Story

As a developer who has just cloned the repo,
I want a single command that brings up all dependencies plus the cockpit-api, agents runtime, and cockpit-ui in dev mode,
So that I am demoing the project within 30 minutes of clone (NFR-RI5).

## Acceptance Criteria

1. **AC1 — `docker compose up -d` brings up the dev infra stack** in containers: Postgres 16, Redis 7+, LocalStack (S3 emulator), Vault Transit (HSM emulator), and IBM watsonx Orchestrate ADK Developer Edition. Each service has a healthcheck; `docker compose ps` shows `healthy` within 60 seconds on a typical laptop.
2. **AC2 — `make bootstrap` installs all workspace dependencies** in idempotent order: Poetry installs across `apps/cockpit-api`, `apps/agents`, `packages/contracts`, `tools/verifier` + pnpm install for `apps/cockpit-ui`. Re-running `make bootstrap` is a no-op when nothing has changed.
3. **AC3 — `make dev` starts all three runtimes in parallel**: cockpit-api on `http://localhost:8000` (uvicorn `--reload`), cockpit-ui on `http://localhost:5173` (Vite dev with HMR), agents runtime via the ADK Developer Edition dev server. `Ctrl-C` cleanly stops all three.
4. **AC4 — cockpit-api `/docs` is reachable** at `http://localhost:8000/docs` (FastAPI's auto-generated Swagger). `/health` returns `{"status": "ok"}`.
5. **AC5 — cockpit-ui shows a "hello cockpit" screen** at `http://localhost:5173`. HMR works: editing `apps/cockpit-ui/src/App.tsx` causes the browser to update without full reload.
6. **AC6 — `make migrate` applies Alembic migrations** to the dev Postgres against the public schema. After this story, the only migration is the empty initial revision generated by Alembic; per-tenant schemas land in Story 1.5.
7. **AC7 — `make seed` creates one demo tenant + one demo officer user** in the dev DB. Seed script lives at `apps/cockpit-api/scripts/seed_dev.py`; idempotent (re-running does not duplicate rows). Demo tenant ID and officer user ID are written to stdout for the developer to use.
8. **AC8 — README "First-time setup" section is end-to-end accurate** — a developer following ONLY the README from clone reaches a "hello cockpit" screen in their browser within 30 minutes (NFR-RI5). Includes prerequisite list (Docker Desktop, Node ≥ 20, Python 3.11+, Poetry ≥ 1.7, pnpm ≥ 9, Make).
9. **AC9 — `make lint` and `make test` are wired** (full execution comes online by Story 1.3 in CI; locally they should already run). `make lint` runs Ruff + mypy + ESLint + Prettier; `make test` runs pytest for each Python project + Vitest in cockpit-ui.
10. **AC10 — `make dev` cold-start budget ≤ 90 seconds** from `make dev` invocation to all three URLs serving (G6). Document the measured cold-start time in the README.
11. **AC11 — `.env.example` documents every dev variable**; `make bootstrap` (or `make dev` if missing) copies `.env.example` to `.env` ONLY when `.env` does not already exist (never overwrites).

## Dev Notes

### Architectural context

[Source: architecture.md#I13 Local dev] — `docker compose up` is the chosen DX investment for NFR-RI5. The five infra services (Postgres + Redis + LocalStack S3 + Vault Transit + ADK Developer Edition) are non-negotiable.

[Source: architecture.md#Development Workflow] — the canonical dev loop is `git clone → make bootstrap → docker compose up -d → make migrate → make seed → make dev`. This story makes it real.

[Source: architecture.md#Build & Deployment] — local dev runs the cockpit-api as a uvicorn process and cockpit-ui as a Vite dev server; agents run inside `apps/agents` as the ADK Developer Edition (single-process). Production combines cockpit-api + agents into one container per A3 — the in-process A3 boundary is preserved here too.

### Critical pitfalls to avoid

1. **`make dev` parallelism**: a naive `&` + `wait` shell pattern leaks zombie processes on Ctrl-C. Use `trap` to forward SIGINT to children, or use `concurrently` (Node) / `honcho` (Python) / `overmind`. Document the choice.
2. **ADK Developer Edition**: confirm the exact CLI command (`orchestrate server`? `orchestrate dev`?) by reading the package's installed CLI help. The story above assumes `orchestrate server` — adjust to whatever the resolved version of `ibm-watsonx-orchestrate` actually exposes.
3. **`.env` handling**: `make bootstrap` MUST use `cp -n` (no-clobber) to avoid overwriting a developer's local `.env`.
4. **Postgres healthcheck timing**: with init scripts, Postgres reports `healthy` only after init completes. If migrations run too soon, they fail. Add a `depends_on: condition: service_healthy` chain or a small retry in `make migrate`.
5. **Redis port collision** is common on dev machines that have local Redis. Either change the host port to `16379:6379` or document the conflict.
6. **`make dev` cold-start**: a 90s budget (G6) means uvicorn `--reload` and Vite + ADK must all fit under that envelope. If the ADK Developer Edition is slow to start (possible — it's a runtime), consider starting it via `docker compose` and have `make dev` skip the ADK process. Document the chosen split.
7. **Seed script schema awareness**: the `tenants` table doesn't exist until Story 1.5 lands. The seed script MUST gracefully no-op (try/except `UndefinedTable`) — re-running after Story 1.5 will then create the demo rows.
8. **Do NOT emulate IBM Cloud HPCS** — Vault Transit is the chosen on-prem/dev fallback per S1. Story 3.2/3.3 swaps in the real KeyVault adapter; this story sets up the dev impl only.
9. **LocalStack must run with `SERVICES=s3` only** — the full LocalStack image is heavy and slow. Story 2.4 (presigned URL flow) confirms the S3 contract; we don't need other services in MVP.

### Architecture patterns relevant here

[Source: architecture.md#Pattern P2 Tenant Scoping] — the seed script writes tenant rows; even though there's no real tenant scoping yet (lands Story 1.8), the `tenants` table is the anchor. Don't introduce any concept of "no tenant" — every demo row belongs to the demo tenant.

[Source: architecture.md#Anti-Patterns to Refuse] — relevant subset for this story:
- ❌ Loading flag in Zustand (use TanStack Query) — irrelevant yet, but `<App />` should not introduce a "loading…" state pattern that violates this when more code lands.
- ❌ Silent failures — `make seed` must explicitly log "schema not yet present, skipping" rather than silent-noop.

### Completion Notes List

- **Deliberate deviation — Subtask 1.5 / AC1.** The IBM watsonx Orchestrate ADK Developer Edition is **not** added as a peer service in `docker-compose.yml`. The ADK CLI's `orchestrate server start` provisions and manages its own docker stack (the `orchestrate server eject` subcommand outputs the underlying compose file). Running it as a peer compose service would race the CLI's container management. Instead, `make adk-up` / `make adk-down` invokes the canonical ADK lifecycle, and the README + `docker-compose.yml` header document the split. This realises pitfall #6 of the Dev Notes ("consider starting it via docker compose and have make dev skip the ADK process") with the inverse direction (the ADK is started out-of-band and `make dev` does not block on it).
- **Subtask 7.1 (FastAPI title/version).** The Story 1.1 scaffold left a bare `FastAPI()`; Story 1.2 explicitly sets `title="Cockpit API"` and `version="0.1.0"` so `/docs` advertises stable metadata.
- **Subtask 6.2 (seed graceful no-op).** Both `tenants` (Story 1.5) and `officers` (Story 1.6) tables are caught individually with `asyncpg.UndefinedTableError`. Each missing table emits an explicit log line ("table not yet present — skipping") rather than a silent no-op (anti-pattern P-AP).
- **Subtask 4.1 (pytest carry-forward).** Story 1.1 already had `pytest = "^9.0.3"` in `apps/cockpit-api`; this story added `pytest`, `pytest-asyncio`, `pytest-cov`, `ruff`, `mypy` to the other three Python projects and wired pytest config + Ruff + mypy in all four.
- **Subtask 5.1 (ESLint+a11y).** `eslint-plugin-react@7` and `eslint-plugin-jsx-a11y` haven't bumped their peer ranges to ESLint 10 yet. Suppressed warnings via `pnpm.peerDependencyRules.allowedVersions`. Documented in README troubleshooting — remove the suppression block once upstream catches up.
- **`.env.example` defaults match compose.** Local services (`DATABASE_URL`, `REDIS_URL`, `S3_ENDPOINT`, `VAULT_ADDR`, `VAULT_TOKEN`) are pre-filled with values that match `docker-compose.yml`, so a fresh clone runs end-to-end without manual edits — except OIDC, which is intentionally blank (Story 1.6).
- **Vitest type-resolution.** `setupFiles` imports `@testing-library/jest-dom/vitest` (not the bare module) so jest-dom's vitest-aware matcher types load without polluting the `expect` global with the jest types.
